# GPT-6.1-Sol 验证交接单

## 任务

按 [Release_Validation_Runbook.md](Release_Validation_Runbook.md) 执行当前 WildVision 的发布前验证，逐项覆盖 R00–R16。先完成可在本机安全执行的自动化与静态核查，再尝试可隔离的 GUI。需要另一台机器、签名账号或 GitHub 仓库的项目标明具体阻塞条件。

这是验证任务，不是修复或发布任务。原始业务代码、真实数据集、现有 dist/release 和用户自动保存文件均不得修改。只允许新建验证报告、隔离测试脚本/夹具/构建副本。不得发布、推送、创建远程仓库、改变访问权限或登录签名账号。

## 工作顺序

1. 阅读发布清单与操作规程，记录环境和候选版身份。
2. 在独立临时目录创建源代码副本、synthetic-home 与合成数据；确认默认数据路径不会落回原仓库。
3. 执行 R01/R02/R03/R04/R06/R08/R09/R10/R11/R12/R13/R14 的本机可执行部分。
4. 对 R05/R07 仅执行具备安全隔离条件的子项；对 R15 如实列出外部待办。
5. 每项失败后保存复现，不修改业务实现；继续独立用例。相同外部阻塞重复出现时停止无效重试。
6. 完成 R16，保存 REPORT.md、results.json、环境信息、源文件清单、脱敏日志及复现脚本。

报告目录：`doc/release/validation/<Asia-Macau时间戳>/`。把实际临时运行目录写入报告，保留可复现脚本。原始密钥、真实数据、完整环境变量不得进入报告。

## 重点防止误判

- 单元测试中的 fake-video、只生成清单，不等于真实视频播放/裁剪成功。
- MP3 HTTP 200 和 FFmpeg 解码不等于 WebView 出声。
- ad-hoc 签名验证通过不等于 Developer ID、公证或 Gatekeeper 下载启动通过。
- 读取 YAML 不等于 GitHub Actions 已运行。
- 真实断电/磁盘满未做时，故障注入要明确其覆盖范围。
- 模型名出现在 API 中不等于运行了模型；当前缓存结果需要如实识别。
- 没有 Git 时以实际源文件清单哈希追溯，不编造 commit。
- 涉及数据丢失的用例必须使用隔离合成副本，不要“先在真实数据上试一下再恢复”。

## 最终交付

向主代理报告：报告绝对路径、各状态数量、最重要的已复现问题、未完成原因、原数据保护检查、是否建议阻断稳定发布。主代理复核证据后向用户汇报，不自动修复或发布。
