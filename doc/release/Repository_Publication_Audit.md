## 实际检查步骤（R01-G，交给 GPT-6.1-Sol）

1. 在独立临时 Git 仓库放入同一份 `.gitignore`，用 `git check-ignore -v --no-index` 对应路径验证规则。覆盖根目录与嵌套的 .env、datasets、证书、包、日志；同时验证源码、锁文件、工作流、正式图标、字体许可、公开指南不被误排除。测试文件使用虚构内容。
2. 在项目根目录执行 `python3 scripts/audit_public_tree.py`。脚本在临时 Git 目录使用实际 Git ignore 语义枚举候选文件，不改原目录 Git 状态，不受开发者全局忽略文件掩盖。输出可重定向到被忽略的本地 validation 目录。
3. 核对输出中的所有 `files`、总大小、`findings`、`tracked_but_ignored`。脚本只输出路径/行号/规则，不输出匹配到的凭据值。退出码 1 表示需复核，不能直接删文件消除提示。
4. 已有仓库时额外核对已跟踪但应忽略的文件，不能以 `.gitignore` 已增加为理由宣称已清理。若发现凭据，停止提交，不复制其值到报告；撤销凭据、历史改写等敏感操作另行处理，未经授权不执行。
5. 对公开候选做人工审查：作者信息、用户名、绝对路径、内部链接、截图、第三方素材、二进制、例子中的真实数据。基础规则扫描没有发现不等于没有敏感信息；原始证据保留本地。
6. 准备提交时先按明确文件范围暂存，查看 `git diff --cached --name-status`、`git diff --cached --stat`、`git diff --cached --check` 与完整 staged diff；复核暂存对象内容，而不只看工作区。禁止靠 `git add -f` 绕过审核。此步骤需进入实际仓库准备阶段后执行，本轮未暂存。
7. 如存在历史，复核所有拟推送 refs 的历史与大对象；工作树干净不能证明历史安全。本项目无 Git，当前历史扫描为不具备条件，不伪造通过。
8. 对打包内容另做清单审查：`.gitignore` 不会限制 PyInstaller `--add-data`，也不会过滤 Release 附件。重点看 examples/public/缓存、个人路径、证书与数据。发布 ZIP/DMG/安装器只装入明确批准的文件。

验收：排除路径全部命中、必需源码与正式资源未误排除、候选列表人工审核、疑似凭据/待确认权利已处理，才进入提交阶段。最终发布与远程推送仍是单独动作。
