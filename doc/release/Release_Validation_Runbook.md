# WildVision 发布验证操作规程

版本：2026-10-21。执行者：GPT-6.1-Sol。配套：[发布清单](GitHub_PreRelease_Checklist.md)、[执行交接单](GPT61Sol_Validation_Handoff.md)。

新增硬性范围：Windows 与 macOS 双平台、普通用户不自行安装开发环境。R01 同时执行 [R01-G 公开内容审查](Repository_Publication_Audit.md)，R15 同时执行 [R15-N 新手安装验收](Beginner_Desktop_Release_Requirements.md)。缺某个平台证据时不能缩为单平台通过。

## 1. 边界、隔离与证据

1. 原项目仅用于只读取样。验证代码、夹具、安装依赖和构建全部放入新的隔离运行目录；不改业务源码、不覆盖原 dist/release，不初始化原目录 Git。
2. 使用 `tempfile.mkdtemp(prefix="wildvision-release-check-")` 创建运行目录，记为 RUN_ROOT。路径必须写进报告；不得复用其他任务的临时目录。
3. 拷贝必要源码与正式资源到 RUN_ROOT/source；排除 .venv、node_modules、.tools、build、dist、release 中的应用、真实 datasets、test _data 和 .git。小型公开样例仅按白名单拷贝。另把现有 release/WildVision.app 复制到 RUN_ROOT/package-under-test；保留包内符号链接。
4. 合成数据放 RUN_ROOT/fixtures，输出放 RUN_ROOT/outputs。设置一个 RUN_ROOT/synthetic-home；不得改写 HOME、用户现有 .wildvision 或真实标注。Python 测试进程可在进程内 patch `pathlib.Path.home` 指向 synthetic-home，并显式设置 `BackendAPI.autosave_dir`；这属于测试隔离，不得把被 patch 的行为当成产品能力已通过。
5. 导入函数即使传了 extract_root，也可能先访问 default_datasets_root。必须从隔离 source 加载模块；检查实际 `__file__`，并确认默认 datasets 指向隔离树。不要让 PYTHONPATH 误加载原仓库。
6. GUI 只使用可确认隔离了数据目录与自动保存目录的实例。需要源码测试入口时，可在临时启动器中构造 BackendAPI、设置测试路径并启动 WebView；报告明确这是源码 GUI，不是安装包端到端通过。无法隔离时停止该子项并记录原因，不在用户现有标注窗口做破坏性实验。
7. 外部发布、上传、创建远程仓库、提交标签、签名账号登录、付费、系统安全设置修改不在本轮执行范围。缺少这些条件时只准备步骤并标状态。
8. 不安装或使用来源不明的软件。允许在隔离目录内按当前锁文件从标准包源安装必要依赖；网络失败记录 blocked，不无限重试。不要修改原环境依赖。
9. 停止整个系统进程、填满真实磁盘、真实压缩炸弹、大规模压测均禁止。故障注入只针对本轮合成路径、受控子进程和小体积夹具。
10. 本轮只验证、不修复。发现问题保存复现脚本、输入和结果，继续执行独立项目。不能偷偷修改标准或源码让结果通过。

报告持久化到 `doc/release/validation/<run-id>/`，目录内至少有：

- `REPORT.md`：摘要、候选版身份、逐项状态、阻断项、待人工验证事项。
- `results.json`：每个用例/子项的状态、方法、实际结果、证据相对路径、限制。
- `environment.json`：系统、架构、解释器、工具与依赖版本；不要保存整个环境变量集合。
- `source-manifest.json`：白名单源文件相对路径和 SHA-256；没有 Git 时不得伪造 commit。
- `logs/`：命令、cwd、退出码、stdout/stderr；敏感值脱敏。
- `repro/`：只操作合成副本的复现脚本和必要小型输入。
- `screenshots/`：实际捕获的界面；不可用绘制稿冒充运行截图。

大视频与安装包留在 RUN_ROOT，报告记录其路径与哈希；不要把几十 MB 夹具重复塞进文档目录。任何证据若只存在临时目录，报告必须说明。报告文件时间使用 Asia/Macau。

每条 results.json 记录至少包含：`id, scope, priority, status, expected, observed, evidence, limitations`。复合用例拆子项；任一必要子项 fail 时不能整项 pass。未执行是 not_run；缺具体外部条件才是 blocked；不适用必须有负责人已确认的范围依据。

## 2. 测试夹具

先查找 ffmpeg/ffprobe。不存在时媒体生成/独立解码标 blocked，其余检查继续。

在 RUN_ROOT/fixtures 生成以下小型视频：

```text
SYN-MP3.mp4：8 秒，320×180，25 fps，H.264 + MP3 440Hz 单声道。
SYN-AAC.mp4：8 秒，320×180，25 fps，H.264 + AAC 660Hz 单声道。
SYN-SILENT.mp4：8 秒，320×180，25 fps，H.264，无音轨。
SYN-BOUNDARY.mp4：8 秒，25 fps，长 GOP，1.0 秒画面由黑转白、音频由静音转音调，用来独立测量裁剪边界。
SYN-24/30/60.mp4：各 3 秒，分别 24/30/60 fps。
```

MP3 夹具参考命令（cwd 必须为夹具目录）：

```sh
ffmpeg -y -f lavfi -i "testsrc2=size=320x180:rate=25:duration=8" -f lavfi -i "sine=frequency=440:sample_rate=44100:duration=8" -c:v libx264 -pix_fmt yuv420p -c:a libmp3lame -shortest SYN-MP3.mp4
```

若构建缺少指定编码器，不应悄悄换成 AAC 后称 MP3 测试通过。记录工具能力与阻塞原因。

为每个媒体保存 ffprobe 的 streams/format JSON 与 SHA-256。使用实际生成文件，不允许用 `b"fake-video"` 进行播放或裁剪验收。

标注夹具：两个同名物种轨道 `Common Crane #1/#2`，行为 `Attending/Eating`。期望区间：轨道 0 Attending [0.2,1.0]，轨道 0 Eating [1.1,1.6]，轨道 1 Eating [2.0,2.8]。25 fps 下帧号应分别为 [5,25]、[28,40]、[50,70]。记录项目当前秒/帧边界约定，不自行改成另一套开闭区间规则。

把同一套文件复制到含中文与空格的隔离目录，例如 `fixtures/中文 样本/`。创建有效 ZIP/TAR、损坏 JSON、缺失视频、重复编号、同名不同目录等小型变体，每例独立 workspace。

## 3. 分项规程

### R00 候选版身份与文件保护（必做，本机可执行）

步骤：记录原目录是否为 Git 仓库、Git commit/dirty（如存在）、源文件清单哈希；记录现有安装包执行文件、Info.plist、JS/CSS、图标哈希与版本；建立隔离副本；记录原真实 datasets/annotations 的只读哈希快照。

判定：身份记录完整、隔离模块路径正确。没有 Git 不阻断后续本机检查，但 Git/tag 对应关系标 blocked；不得把“已记录无 Git”当成发布 Git 准备通过。结束时复核未写原数据；外部并发变化需区分，不可自行覆盖恢复。

证据：environment.json、source-manifest.json、候选包清单、保护路径前后哈希。

### R01 提交内容、许可证与文档（必做，部分需负责人）

步骤：根据源码用途提出提交白名单，检查 .gitignore 是否覆盖实际数据/构建产物/环境文件；只读扫描公开候选文档中的绝对路径与个人信息；列出 LICENSE、第三方声明、数据再分发说明、README 快速开始、平台范围、版本是否存在且互相一致。

判定：没有 LICENSE 或来源说明时标“缺少材料”，不能自行选择许可或宣告数据可再分发。版权归属与首发范围需负责人决定，标 blocked。已有文档若宣传未实现功能，记录 fail 与准确位置。

证据：候选文件清单、排除建议、文档缺口列表；只列路径/问题类型，不复制隐私值。

### R02 敏感信息与本地服务（必做，分子项执行）

准备：扫描白名单源码与文档，不扫描用户整个 home；密钥匹配结果只记录路径、行号、规则和脱敏摘要。可用已安装的扫描器，缺工具时基础规则扫描必须注明覆盖不足。

步骤：独立启动隔离 LocalMediaServer，只绑定回环地址。发布合成视频，测试合法 token、错误 token、越界 rel、缺失文件、HEAD、GET、有效/无效 Range。使用 http.client/urllib 与短超时，保存响应码与头部。对 POST /upload 只传几字节合成文件，测试无会话标识、外部 Origin 等条件下是否能写入隔离目录；不要请求任何真实文件。

判定：不能越界读取/写入；非授权来源不应取得本地写能力；请求失败不泄露本机敏感路径。CORS 响应头或静态源码问题可以作为证据，但 HTTP 客户端测试不等于浏览器攻击已证实，需区分。无 body 限制等设计问题标“静态发现”，不发超大请求验证。

证据：请求/响应摘要、合成落盘文件清单、最小复现与静态发现。`127.0.0.1` 绑定通过不能覆盖写接口授权失败。

### R03 干净构建与现有测试（必做，本机可执行）

准备：在隔离 source 创建全新虚拟环境与 node_modules，不拷贝开发机现有安装包。依赖按 requirements-desktop.txt、package-lock.json 安装；记录解析出的精确版本与 Python/Node 版本。

步骤：

```text
1. 在隔离 source/ui 执行 npm ci。
2. 在同目录执行 node --test tests/*.test.cjs。
3. 在同目录执行 npm run build（包含 tsc --noEmit）。
4. 在隔离 source/core 用隔离 Python 执行 unittest discover -s . -p 'test_*.py' -v。
5. 使用临时测试包装器 patch pathlib.Path.home 指向 synthetic-home，包住后端测试运行全过程；记录包装器代码。
6. 在隔离 source 执行 build_desktop_app.py，构建脚本内部也执行测试，必须沿用隔离 home 包装器，防止 autosave 写原 home。
```

判定：命令退出码 0、全部测试逐项通过、产物实际生成。任何 skipped 单列。测试中 fake-video 与仅校验列表文件的场景不算媒体端到端通过。网络/工具缺失与产品缺陷分别标 blocked/fail。

证据：安装日志、pip freeze、Node/npm 版本、完整测试与构建日志。测试数以本次实际输出为准，不硬编码历史 43。

### R04 包内一致性、版本、架构与品牌（必做，本机可执行）

步骤：分别检查现有 release 包与本轮隔离重建包；读取 Info.plist、file 输出、codesign 详情；比较其 JS/CSS/图标/字体与对应源码构建输出。提取 PyInstaller 的 desktop.media_server 字节码，确认新音轨路由真实存在。读取 CFBundleIconFile 并验证对应资源存在，反解 ICNS 检查缩放图像；检查 HTML favicon 的相对路径能在包内解析。

判定：每个包内部与自身对应构建一致。不同构建之间不能要求所有二进制哈希完全相同；差异需说明原因。版本不一致、0.0.0、架构误标分别记录 fail。ad-hoc 与 Developer ID、公证状态分别报告，codesign --verify 通过不代表后两者通过。

证据：包清单、版本比较、签名命令输出、图标预览。生成包的测试结果不可反向当成旧发布包也通过。

### R05 打包后解压与安装位置（必做，本机与外部两层）

步骤：仅对副本执行 `ditto -c -k --sequesterRsrc --keepParent <App> <候选.zip>`，解压到全新隔离目录；比较执行权限、符号链接与包签名；记录最终 ZIP SHA-256。将副本放入隔离的 `Applications-like/` 目录，验证资源解析。若需要 GUI，先满足第 1 节隔离条件。

判定：封装/解压不得损坏可执行权限、相对链接或签名。仅在本机移动目录不等于干净电脑验证，也不等于浏览器下载后的 Gatekeeper 验证。后两项移交 R15，不能勾选通过。

证据：打包命令、权限/链接清单、解压后签名输出、SHA-256、启动记录或阻塞说明。

### R06 音轨提取与 HTTP 服务（必做，本机可执行）

步骤：分别用当前源码服务与现有发布包中提取的服务类，发布 MP3/AAC/无音轨合成文件。对 MP3 请求 `<video_url>.mp3`，获取完整数据、HEAD、Range bytes=0-1023；验证 200/206、audio/mpeg、Content-Range 与实际长度。对响应音频用 FFmpeg 独立解码，并测量 RMS/峰值确认不是全静音。AAC/无音轨不得返回伪装成 MP3 的不可解码数据；记录回退响应和前端回退逻辑。

判定：MP3 可正常提取与解码、Range 一致、错误输入不崩溃。AAC/无音轨未命中 MP3 路由属于可接受的回退前提，不代表其界面播放已通过。

证据：ffprobe 输入、HTTP 输出、音频解码日志、源文件与响应哈希。此用例只验证媒体服务，不能声称扬声器有声。

### R07 真实播放器操作与声音（必做，需可隔离 GUI；听觉部分可需人工）

步骤：在隔离 GUI 依次打开 MP3、AAC、无音轨样例；点击播放/暂停；分别跳转到 1/4/7 秒；静音再取消，音量设为 0/50/100；播放中切换视频并离开卡片；验证首尾及逐帧。使用实际媒体元素状态/错误、截图、录屏等证据，不能只靠 play() Promise 成功。

判定：画面与时间推进正常；暂停/换卡后旧音频不继续；无音轨不显示误导性错误；有声音频不因路由或播放权限失败而静默。用可测的同步脉冲验证时，记录至少三个时点音画误差；建议验收线为绝对误差 ≤120ms，作为本轮目标而不是既有产品保证。没有系统音频捕获或人工听验时，“实际出声”标 blocked，解码通过不得替代。

证据：逐动作记录、播放器错误、关键时点与音频证据；源码 GUI 与最终包 GUI 分开记录。

### R08 演示/模型输出真实性（必做，本机可执行）

步骤：检查 AIEngine 的两个入口；对不同视频/标签/查询调用并记录 runtime、返回结构与缓存来源；检查其结果是否依赖 GT、是否真实运行模型。核对公开 UI、README、导出内容中对这些能力的表述。不要为本轮下载大模型。

判定：可以明确保留演示功能，但必须标识为演示，不能把缓存或由 GT 派生的预测标为真实评测。若功能目前无公开入口，报告“API/代码存在、发布是否承诺待确认”，不要凭类名推断已向用户开放。

证据：调用输入输出的脱敏摘要、调用路径、实际 UI/文档文案及差异。

### R09 视频裁剪与缺依赖（必做，本机可执行，分子项）

步骤：用真实可解码合成媒体裁剪 [0.2,1.0]、[1.1,1.6]、[7.0,8.0]，并测试非法/越界区间；检查 cut_errors，而不只看外层 ok。对裁剪结果做 ffprobe 和完整解码，测量时长、音轨与首尾内容。用 SYN-BOUNDARY 的独立视听事件测量边界，不以函数输入当作实际输出。

分别测试现有 FFmpeg 路径、缺 FFmpeg 的路径、缺 FFmpeg/OpenCV 的路径。路径缺失可在受控进程里 patch shutil.which，不卸载主机软件；模拟缺依赖不等于真正干净机器测试。OpenCV 不可用时该分支 blocked。

判定：不得把仅生成 mmaction2_annotations.txt/grounding_annotations.json 当成裁剪成功；损坏/缺失片段应准确呈现失败。建议精确裁剪验收线为边界误差 ≤1 帧，若流复制达不到，记录 fail 并说明可以由负责人选择公开其近似行为；不可自行放宽标准。音轨丢失要和发布承诺对应判定。

证据：各分支输入、返回值、cut_errors、ffprobe、解码与边界测量。记录使用流复制还是重编码。

### R10 标注与导出往返（必做，本机 API 与 GUI 分层）

步骤：导入第 2 节的真实合成样例，使用 BackendAPI 选择两个同名物种轨道并创建三段；确认 dirty；保存；用独立 json 读取器检查轨道索引、行为、数量、时间与帧号；重新构造 API 并打开同一隔离数据集；导出 ZIP/合并 JSON 后导入到另一全新 workspace。

判定：忽略生成时间等非语义字段后，动物轨道顺序、标签、时间边界和片段数量一致。同名物种必须按轨道索引区分。验证 [0.2,1.0]→[5,25] 等预先给定的结果，不调用被测转换函数生成“期望值”。重复导出不得静默删除未选卡片。

补充：单独验证撤销/重做、选中两段复制到新播放位置、越界粘贴和无合法行为。GUI 快捷键操作单独记录，不用 API 调用冒充。

证据：原始夹具、API 步骤、保存/导出 JSON、独立语义比较结果；不要提交真实标注。

### R11 未保存离开、写入失败与恢复（必做，只允许合成副本）

步骤 A：保存基线三段；再改一段；分别测试 leave_card("check")、放弃、保存并离开；每个分支重新恢复基线，不共享前一用例的脏状态。检查磁盘与内存是否符合操作选择。

步骤 B：在合成目标文件的写入边界注入 PermissionError 与 OSError(ENOSPC)。只对该明确路径注入；别 patch 所有文件写入。再注入“文件被截断后只写入部分 JSON 随即失败”，保存原始有效副本以供比对。不得真的填满磁盘。

步骤 C：显式指定合成 autosave_dir，自动保存后创建新 API 恢复；验证恢复提示、dirty 状态与实际主文件一致。额外测试两个数据集中同名 video 的自动保存，确认不会无提示覆盖/误恢复。

判定：错误被明确报告；不得把未持久化内容标为已保存；最后有效标注仍存在且可恢复。若原文件已截断损坏，标 fail 并保存复现，不替产品自动修复。注入证明的是对应故障路径，不足以宣称真实断电测试通过。

证据：故障注入脚本、修改前后哈希、JSON 可解析性、API 返回值、恢复比较。清理仅限本轮临时副本。

### R12 时间/帧率与统计口径（必做，本机可执行）

步骤：对 24/25/30/60 fps 的合成素材检查元数据与设置；独立计算指定时间到帧号（当前约定为非负值四舍五入，半帧向上，确认公开说明一致）。检查视频结束时不越界。变帧率若无明确支持，不自动宣称支持。

独立统计三个片段、两个同名轨道、两个行为的片段数/轨道数/已标标签数，区分标签覆盖与逐个体完整标注。tIoU 小样例：[0,2] 与 [1,3] 为 1/3；相同为 1；不相交为 0；空标注、不同轨道匹配另测。

判定：数值与独立期望一致，指标定义不会误导用户。公开函数输出若使用另一种合理聚合口径，记录定义差异并检查文档，不随意改科研语义。分母为零等情况应明确处理。

证据：手工期望、计算脚本、实际结果与对比。

### R13 CI、源码启动与发布流程静态核查（必做，本机可执行静态部分）

步骤：检查 .github/workflows/release-desktop.yml 触发条件、Python/Node 版本、测试命令、产物路径、缺产物行为、架构标签、权限、是否创建 Draft/Release。检查 Start_Mac.command、Start_Windows.bat、Build_Windows_Exe.bat 在没有 ui/dist 时的完整流程。不得通过执行它们去改原环境。

判定：缺前端测试、只在 tag 后验收、直接上传 .app、版本漂移等按影响记录具体问题。未创建远程仓库时，Actions 实际运行/Release 下载只能 blocked；静态 YAML 看起来正确不算 CI pass。

证据：精确文件/行号、缺口清单、预期发布顺序与外部待办。

### R14 压缩包、重导入与可控资源限制（必做，只允许小型合成夹具）

步骤：制作 ZIP/TAR 包含 ../、绝对路径、符号/硬链接、同名成员、损坏 JSON；在 sandbox 父目录放 sentinel 文件，并记录前后哈希。导入后枚举全部创建路径，检查是否全部限制在预期 workspace 内。另测试把恶意路径清洗成正常路径后是否覆盖已有合法成员，不能只查“没有越界”。

重复导入同一个包到相同显式 extract_root，先加入合成标注，再观察是否被清除；仅对该用例副本执行。若实际 UI 使用另一个独立目录策略，分别记录 API 与 UI 风险，不扩大归因。

体积限制：在测试进程临时将 MAX_ARCHIVE_TOTAL_BYTES 下调到数 KB，用几十 KB 的夹具触发阈值；只验证拒绝与残留处理。文件数限制只做静态核查与小型压力测试，不制造真实压缩炸弹。

判定：无目录外写入/链接逃逸；非法输入不静默污染有效数据；重导入覆盖有明确策略与提示；超过限制有明确错误。受控阈值测试不能证明 20GB 场景性能。

证据：包成员清单、sentinel 哈希、创建文件列表、返回值、重导入前后语义比较。

### R15 外部机器与分发信任（必做，缺环境时 blocked）

需要：承诺支持的 macOS/Windows 机器或 VM；未经项目开发环境污染的用户环境；最终可下载附件；签名/公证策略由负责人确定。

人工操作：浏览器下载候选附件→核对 SHA-256→解压→放入正常安装目录→启动→导入合成 ZIP→播放并听验→创建三段→保存→退出→重开→验证→导出。记录每步截图、系统/架构、耗时、对话框和错误原文。检查断网使用与 FFmpeg/WebView2 缺失场景。

判定：支持平台上独立完成流程，数据一致。不得关闭系统安全保护或删除隔离标记来制造“首次启动通过”。若遇到身份/公证要求，记录并交负责人处理。源码 WebView、同一开发机的新目录都不等价于此项。

### R16 最终准入与追溯（必做，含负责人决策）

步骤：汇总 R00–R15 子项；将每条 fail/blocked 映射到发布清单与受影响平台/功能；给出最小修复建议，但本轮不实施。所有问题需附可复现证据和严重度理由。列出待负责人确认的许可证、平台、签名、演示功能和版本决策。

判定：未测不算通过；核心数据安全失败不能靠“预览版”标签豁免。负责人确认缩小范围后才能把相关项改 not_applicable。证据对应当前附件哈希；不得把此前 43 项通过或本次脚本退出 0 等同整体可发布。

输出最终结论只能选：`本机验证通过，外部验收待完成` / `发现发布阻断项` / `验证受阻，证据不足`，并解释适用范围。本轮不执行真正 GitHub 发布。
