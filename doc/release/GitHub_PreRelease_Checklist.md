## 状态与发布规则

- `pass`：规定步骤实际完成，结果符合标准，有可追溯证据。
- `fail`：观察到与标准不符的结果；给出最小复现与影响。
- `blocked`：缺少必需外部条件，例如目标机器、账号、待定产品决策。
- `not_run`：尚未执行；未执行不能写成 blocked 或 pass。
- `not_applicable`：有明确理由且对应功能/平台已从发布承诺中排除。
- 未填写的复选框表示待验收。历史测试通过不能自动勾选当前候选版。
- 必做项失败会阻断受影响功能/平台的稳定发布；可选择修复，或由负责人明确缩小发布范围。预览版也必须满足数据安全、敏感信息和功能描述真实性要求。
- 附件哈希、源代码清单、构建环境共同标识候选版。代码或产物变化后，重跑受影响用例。

## A. 发布范围与真实性（必做，R00 / R08 / R13 / R16）

- [ ] 同时交付 Windows 与 macOS 面向普通用户的安装包；源码作为独立的开发者入口。
- [ ] 明确预览版/稳定版、最低系统版本和 CPU 架构，不用构建成功代替兼容性实测。
- [ ] 统一 Git tag、前端、应用包、附件名和更新日志的版本号。
- [ ] 人工标注、统计、质检、裁剪、模型推理各自列出真实可用范围。
- [ ] 离线缓存、合成视频、演示标签、演示指标在界面、文档和输出中明确说明。
- [ ] 支持的平台和功能都有对应的验收证据。

## B. 仓库准备（必做，R01 / R02）

- [ ] 初始化 Git 前完成提交白名单；源码、测试、正式资产、必要文档进入仓库。
- [ ] 忽略虚拟环境、node_modules、构建目录、安装包、实际数据集、日志、自动保存、环境变量与凭据文件。
- [ ] 测试夹具与真实数据分开，允许分发的样例按白名单保留。
- [ ] 审查课程文档、个人信息、开发提示词、绝对路径及压缩包内容。
- [ ] 对最终待提交内容完成敏感信息扫描并人工复核；不公开原始密钥值。
- [ ] 二进制安装包使用 Release 附件；大视频、模型权重另行确定存放策略。
- [ ] 完成根目录 LICENSE、版权归属和第三方声明；样例数据再分发权限逐项核对。
- [ ] 提交前复核暂存文件列表、文件大小、作者信息及许可证范围。

## C. 构建与依赖（必做，R03 / R04 / R05 / R09）

- [ ] 从干净的独立副本安装依赖并构建，不复用已有 ui/dist。
- [ ] 明确 Python/Node 与目标平台版本，解决本机和 CI 基线差异。
- [ ] 保留前端锁文件；Python 依赖具备已验证的锁定/约束方案。
- [ ] 源码启动流程包含前端构建，文档可从零执行。
- [ ] 后端测试、前端测试、类型检查和生产构建通过。
- [ ] FFmpeg/OpenCV 等可选依赖在缺失时给出准确提示；支持范围与发布说明一致。
- [ ] 包内前后端、图标、字体、样例来自同一候选版本。
- [ ] 记录依赖版本、源代码清单哈希、构建日志与最终附件哈希。

## D. 核心业务正确性（必做，R06 / R07 / R09 / R10 / R11 / R12）

- [ ] 文件夹、ZIP、单视频及承诺支持的其他导入方式验证通过。
- [ ] 中文/空格路径、重复导入、缺失视频、损坏数据和不支持编码处理明确。
- [ ] 播放、暂停、逐帧、拖动、首尾边界及切换视频正常。
- [ ] MP4 内 MP3、AAC、无声视频分别检查；声音同步、静音、音量、暂停和换卡行为正确。
- [ ] 帧率与秒/帧转换一致；可变帧率支持策略清楚。
- [ ] 同物种多轨道不会混淆；新增/编辑/复制/粘贴/撤销/重做结果正确。
- [ ] 保存、重启、重新打开后标签、轨道、数量和区间边界保持一致。
- [ ] 未保存离开的保存/取消/放弃路径正确。
- [ ] 导出后用独立方式读取并重新导入，完成语义一致性比对。
- [ ] 裁剪结果可解码、时长与区间准确性满足公开声明；声音保留策略明确。
- [ ] 完成率、标签覆盖率、tIoU 等统计有独立小样例核算。

## E. 数据安全（必做，R02 / R10 / R11 / R14）

- [ ] 故障、恢复、删除与覆盖测试全部运行在隔离的合成副本。
- [ ] 保存失败/中断不会静默损坏最后有效标注，错误不会显示为成功。
- [ ] 自动保存与恢复不会混用同名视频或其他数据集的状态。
- [ ] 重复导入、移除卡片和导出覆盖的影响可预测且不静默丢失标注。
- [ ] 压缩包路径穿越、符号链接、损坏成员与体积限制有验证证据。
- [ ] 本地服务的文件边界、写接口、来源校验、上传限制有检查与受控测试。
- [ ] 不可信标签/文件名不会执行脚本，导出内容正确转义。
- [ ] 依赖安全问题已评估适用性，未用“扫描工具没报错”代替风险判断。

## F. 分发与安装（必做，R04 / R05 / R15 / R16）

- [ ] macOS .app 以保留权限和符号链接的 ZIP 封装；Windows 程序及必要运行组件装入独立 ZIP；两者注明实际架构。
- [ ] 明确 ad-hoc、Developer ID、公证各自状态；按目标发布等级执行分发策略。
- [ ] 从最终下载附件在干净目标机器上安装、启动、导入、标注、保存和重开。
- [ ] 从常用安装目录和不可写安装位置运行时，用户数据写入合适的用户目录。
- [ ] Windows 发布前完成 WebView2 自动部署、非管理员、中文路径及真实 Windows 机器验证。
- [ ] 双平台在无 Python/Node/Git/FFmpeg 的干净机器上完成安装、首次启动、标注和带声裁剪；缺运行组件由安装包处理，不能交给用户手动安装。
- [ ] 更新软件后旧数据可读；格式变化有迁移说明或版本限制。
- [ ] 测试包与上传包哈希一致；上传后重新下载核对。

## G. CI 与发布维护（R13 / R16）

- [ ] 必做：提交/PR 检查包含后端、前端测试与构建，缺失产物应失败。
- [ ] 必做：实际二进制架构与附件命名一致；构建权限最小化。
- [ ] 必做：Actions artifact 与 GitHub Release 附件分别配置；先准备 Draft Release。
- [ ] 必做：最终附件有 SHA-256 校验值和版本说明。
- [ ] 必做：README 提供用途、截图、下载、支持范围和五分钟入门。
- [ ] 必做：数据格式、演示功能、已知限制、日志路径和故障处理写清楚。
- [ ] 建议：Issue 模板、贡献指南、安全反馈渠道、引用说明和依赖清单。
- [ ] 建议：由未参与开发的人仅靠下载包和文档完成首个标注流程。
